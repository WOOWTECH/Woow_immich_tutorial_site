Chapter 12

Troubleshooting and maintenance

When you run into problems like a failed upload, blurry thumbnails, stuck jobs or a version update, work through the problem in order and leave notes that someone else can pick up. By the end of this chapter, you'll no longer be gambling on "just restart it and see"; you'll systematically find where the problem is.

Find evidence before you fix anything

When something goes wrong with your photo library, the most common mistake is to gamble: "restart it", "upload again", "delete things at random". Those actions usually wash away the most useful clues. The right approach is to calmly write down the symptom first, work through the layers, and only act once you have evidence.

Chapter task: learn a layered troubleshooting routine, use it on common problems such as uploads, thumbnails, jobs and updates, and leave notes that someone else can pick up.

Work through the layers, outside in

LayerWhat to checkTypical signal
Your deviceNetwork, browser, app versionOnly you cannot open it; everyone else is fine
The entry point (Tunnel)Whether the URL opens, whether there is a certificate warningThe browser shows "cannot connect" or "Not secure"
The Immich serverServer status, jobs, storage space"Server Offline", stuck jobs, storage full
The data layerThumbnails, AI analysis, backupBlurry thumbnails, search finds nothing, backup does not run
Narrow the scope first: asking "Is it just me, or is it everyone?" immediately tells you whether the problem is "your device" or "the server".

Six steps to troubleshoot

  1. Write down the symptom and the time

    Note when it happened, what you were doing, and what error message you saw. Without a time there is no trail to follow.

  2. Confirm the scope

    Try another device, or ask someone else to try, to tell whether it is a problem with your own device or one that affects the whole site.

  3. Check layer by layer, outside in

    Network → entry point → server status → data layer; rule out one layer at a time.

  4. Find the first clear error

    Error messages, the status of the jobs, storage usage: find the first point where things went wrong, and do not get dragged along by the chain of errors that followed.

  5. Make the smallest fix

    Change only the one variable most likely to be the cause, then verify. Do not change many things at once.

  6. Leave a record

    Record "symptom → diagnosis → action → result", so you can hand it over later or refer back to it if the problem comes back.

SymptomLikely causeFirst thing to do

Updates and backups

Updates (admins): when "NEW VERSION AVAILABLE" appears in the top right, a new version is out. Before you update, always:

  • Read the official release notes first and confirm there are no breaking changes (especially for a major-version upgrade, such as v2 → v3).
  • Back up the database and the settings before you update.
  • Update during an off-peak window, so you do not disrupt your family while they are using it.

Backups: the biggest fear with a self-hosted photo library is something happening to the server. Admins should check regularly that the backup mechanism (the database and the photo files) is actually running, and do a restore drill when needed.

Back up before you update: "It broke, and you only found out after the update" is the most painful scenario. Without a backup, do not touch a major-version update.

Troubleshooting FAQ

The problem keeps coming back. How do I avoid that?
Keep the "symptom → diagnosis → action → result" notes from last time. When it comes back, compare against the notes; you can usually pin it down quickly instead of groping in the dark all over again.
Can I restart the server myself?
That depends on whether you have access to the server. Regular users do not, and should not restart it on a whim; ask the admin to handle it, and write down the symptom first.
How long should I wait when jobs are stuck?
First check the Jobs page to see whether the jobs are still moving (whether there is progress). With a large number of photos, several hours is normal; you only need to step in when it has stopped completely.
How do I report a problem to the admin?
Include the time, what you did, the error message you saw (redact sensitive information in screenshots), and the scope (just you, or everyone). The more complete it is, the easier it is to deal with.
The interface changed after an update and I cannot find a feature. What now?
Interface changes are normal. Read the official release notes and the latest docs first. This guide is based on v2.5.x; where they differ, the latest version wins.
