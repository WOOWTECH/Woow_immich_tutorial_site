第 12 章

排錯與維護

遇到上傳失敗、縮圖模糊、jobs 卡住、版本更新等問題時，照順序排查並留下可交接的記錄。讀完這章，你不會再靠「重開看看」碰運氣，而是有系統地找到問題所在。

先找證據，再動手修

相簿出問題時，最常見的錯誤就是「重開」「重傳」「亂刪」碰運氣。這些動作往往把最有用的線索洗掉。正確做法是：先冷靜記錄現象，分層排查，找到證據再動手。

本章任務：學會一套分層排錯流程，處理上傳、縮圖、jobs、更新等常見問題，並留下可交接的記錄。

從外到內分層排查

層檢查什麼常見訊號
你的裝置網路、瀏覽器、App 版本只有你打不開、別人正常
入口（Tunnel）網址能不能開、有沒有憑證警告顯示「無法連線」或「不安全」
Immich 伺服器伺服器狀態、jobs、儲存空間「Server Offline」、jobs 卡住、空間滿
資料層縮圖、AI 分析、備份縮圖模糊、搜不到、備份不跑
先縮小範圍：問「只有我這樣，還是大家都這樣？」能立刻把問題定位到「我的裝置」還是「伺服器」。

六步排錯流程

  1. 記錄現象與時間

    記下「什麼時候、做什麼、看到什麼錯誤訊息」。有時間才有線索。

  2. 確認範圍

    換個裝置或請別人試試，判斷是個人裝置問題還是全站問題。

  3. 從外到內逐層查

    網路 → 入口 → 伺服器狀態 → 資料層，一層層排除。

  4. 找第一個明確錯誤

    錯誤訊息、jobs 狀態、儲存用量，找到「第一個」出錯的點，不要被後續連鎖錯誤帶走。

  5. 做最小修正

    只改最可能的那一個變數，改完驗證。不要一次動很多東西。

  6. 留下記錄

    把「現象 → 判斷 → 動作 → 結果」記下來，方便日後交接或復發時參考。

現象較可能原因先做什麼
上傳失敗網路不穩、檔案過大、空間不足重試、分批、看儲存用量
縮圖模糊或空白縮圖 jobs 未完成或積壓到 jobs 頁看狀態，等它跑完

更新與備份

更新（管理員）：右上角出現「NEW VERSION AVAILABLE」表示有新版。更新前務必：

  • 先讀官方 release notes，確認沒有破壞性變更（尤其跨大版本，如 v2 → v3）。
  • 先備份資料庫與設定，再更新。
  • 選離峰時間更新，避免影響家人使用。

備份：自架相簿最怕伺服器出事。管理員應定期確認備份機制（資料庫、照片檔案）有在運作，必要時做一次還原演練。

更新前必備份：「更新後才發現壞掉」是最痛的情境。沒有備份就不要動大版本更新。

排錯常見問題

問題復發，怎麼避免？
把上次的「現象 → 判斷 → 動作 → 結果」記錄留下來。復發時對照記錄，通常能快速定位，而不是重新瞎子摸象。
可以自己重開伺服器嗎？
要看你有沒有伺服器權限。一般使用者沒有，也不該亂重開；請管理員處理，並先留下現象記錄。
jobs 卡住要等多久？
先看 jobs 頁是否還在動（有進度）。大量照片時跑幾小時正常；完全停住不動才需要介入。
如何回報問題給管理員？
附上「時間、做了什麼、看到的錯誤訊息（截圖遮掉敏感資訊）、影響範圍（只有我還是所有人）」，越完整越好處理。
更新後介面變了找不到功能，怎麼辦？
介面改版是常態。先看官方 release notes 與最新文件，本教學以 v2.5.x 為準，若有出入以最新版本為準。
